# 車輛紀錄資料品質與同步保護設計

## 目標

在不改變現有新增、編輯、刪除與還原流程的前提下，修正費用分類錯誤、讓明顯的里程與油耗異常可見，並降低整批雲端覆寫造成資料遺失的風險。

## 已核准範圍

1. 明確的紀錄類別優先於詳細文字關鍵字，避免「改裝升級」因為內容含「濾網」而被算入保養維修。
2. 分析頁新增精簡的「資料檢查」區塊，列出日期／里程倒退與加滿油耗異常。
3. 異常油耗在加油分析列中以文字標記，不靠顏色單獨表達。
4. 前端同步使用雲端資料指紋做樂觀衝突檢查；發現雲端版本不同時保留本機資料並停止覆寫。
5. Apps Script 在整批覆寫前建立伺服器端快照，並阻擋空陣列或異常大量刪減；已確認的完整還原可明確允許大量替換。

## 不在本次範圍

- 不加入多人帳號、角色或協作權限。
- 不重做篩選器、圖表或加油卡片版面。
- 不改造既有六欄 Google Sheet 主資料格式。
- 不自動修正正式紀錄，也不自動排除任何油耗資料。
- 不新增總價、已付與尾款欄位；這項需求保留到後續資料模型改版。

## 前端設計

### 費用分類

`getOwnershipCostBuckets()` 先依 `category` 做固定映射：保養／維修／更換歸入保養維修，加油歸入燃料加油，保險與檢驗／稅費歸入保險稅費，改裝升級歸入配件改裝。只有「其他」或未知類別才使用詳細內容與備註的關鍵字補判斷。

### 資料檢查

新增純函式產生問題清單：

- 依日期彙整當日最高里程；若某日最高里程低於更早日期已出現的最高里程，建立里程倒退問題。
- 對至少五個有效的加滿區間計算中位數；區間油耗高於中位數 45%、低於中位數 30%，或超出 5–18 km/L 時，建立油耗異常問題。
- 問題只提示「請確認里程、是否漏登、是否真的加滿」，不判定哪一筆一定錯誤。

分析頁在持有成本摘要下方顯示資料檢查。沒有問題時顯示「未發現明顯異常」；有問題時顯示數量、日期、數值與建議檢查方向。加油分析對應的油耗值附加「待確認」文字。

### 同步衝突

前端初始化優先讀取 `?action=syncState`，取得 `{ records, fingerprint, updatedAt }`；若後端尚未支援則相容舊的陣列回應。儲存時傳送 `{ records, expectedFingerprint, allowDestructiveReplace, reason }`。

後端回傳 `conflict` 或安全檢查失敗時，前端不得宣稱已同步；本機 `localStorage` 保留目前資料，並提示使用者先匯出備份或重新整理確認。完整還原流程會傳送 `allowDestructiveReplace: true`，一般新增、編輯與單筆刪除不會。

## Apps Script 設計

### 雲端狀態

`syncState` 使用與既有 GET 相同的讀取結果，另回傳正規化 JSON 的 SHA-256 指紋。舊的預設 GET 仍回傳陣列，避免破壞既有讀取者。

### 寫入安全檢查

`doPost()` 同時接受舊陣列與新 envelope。新 envelope 若帶有 `expectedFingerprint`，必須與目前工作表一致，否則不清除、不寫入並回傳 `conflict`。

除非 `allowDestructiveReplace` 為真，以下操作會被拒絕：

- 雲端已有資料時寫入空陣列。
- 一次刪除超過 3 筆且新筆數少於原本的一半。

每筆資料必須是物件，日期／類別／詳細內容／備註為可轉字串值，里程與費用必須是有限且非負的數字或空值。單次寫入最多 5,000 筆。

### 寫入前備份

通過驗證後、清除主資料前，將目前完整資料寫入「保養紀錄備份」工作表。每列包含備份時間、批次 ID、原因與原本六欄資料。保留最近 20 個批次，舊批次整批刪除。

## 錯誤處理

- 衝突、安全拒絕與網路失敗都保留本機資料。
- 後端建立備份失敗時不得繼續覆寫主資料。
- 備份工作表不存在時自動建立並寫入欄名。
- 舊前端送出的陣列仍可寫入，但同樣套用資料驗證、破壞性寫入限制與寫入前備份。

## 測試與驗證

1. 前端單元測試覆蓋明確類別優先、里程倒退、油耗異常、資料檢查渲染、同步 envelope 與衝突提示。
2. Apps Script 單元測試以 VM／假工作表覆蓋指紋一致、指紋衝突、空陣列拒絕、大量刪減拒絕、明確允許還原與備份先於清除。
3. 執行完整 `node --test`、inline JavaScript 編譯與 `git diff --check`。
4. 以 375px 瀏覽器確認資料檢查區塊沒有水平溢出，且異常文字可讀、無 console error/warning。
5. 部署時先更新向下相容的 Apps Script，再發布前端；只驗證正式 GET／`syncState`，不對正式資料執行測試 POST。
