# 同步合併、7,500 km 保養與操作體驗改版設計

## 目標

1. 修正會遺失資料的同步路徑：重新開啟時覆蓋未同步的本機資料、連續儲存互相衝突、讀取失敗後略過衝突檢查。
2. 定期保養改為每 7,500 km 或 12 個月追蹤，並依開車速度預估到期日。
3. 修正關鍵字誤判（「保險桿」算成保險、「輪胎換位」重置換胎）。
4. 改善輸入與防手滑體驗、加油分析，以及首次載入與離線使用。

## 不在本次範圍

- API 存取權限（共用密碼）：只有車主本人使用，暫不處理。
- Google Sheet 欄位改版（加入紀錄 ID、拆出加油欄位）：本次以「整筆紀錄內容」做合併已解決主要問題，改欄位需要搬移正式資料，風險較高，留待之後。
- 把邏輯拆成多個模組：先拆成 `index.html`、`styles.css`、`app.js` 三個檔案，測試仍以假 DOM 載入 `app.js`。

## 同步設計

本機保存三樣東西：工作中的紀錄、`baseRecords`／`baseFingerprint`（上次確認過的雲端版本）、`dirty` 待同步標記。上傳中的內容另存為 `lastAttempt`，用來判斷沒有收到回應的寫入是否其實已寫進雲端。

- 所有同步排成單一佇列；佇列執行中的新儲存會合併成下一次上傳。
- 沒有雲端版本時先讀 `syncState`，絕不送出缺少 `expectedFingerprint` 的寫入。
- 與雲端比對（開啟 App、衝突、手動或自動重試時）：
  - 本機沒有待同步變更：直接採用雲端資料。
  - 雲端仍等於 base（或使用者確認整批還原）：直接上傳本機版本。
  - 兩邊都有變更：以整筆紀錄內容為單位做三方合併。每筆內容的數量依「本機沒變就用雲端、雲端沒變就用本機、兩邊一樣就照做、真的衝突取較多者」決定，所以新增、修改與刪除都不會被另一邊蓋掉；最壞情況是留下兩個版本，由資料檢查的「可能重複」提示處理。
- 編輯類視窗開著時不替換紀錄陣列（它們以索引指向正在編輯的紀錄），關閉後再同步。
- 連線恢復、App 回到前景、點同步狀態，或重試計時器（15 秒起，每次加倍，最多 5 分鐘）都會觸發同步。
- 第一次使用新版時沒有同步狀態：若本機資料與雲端不同，改用雲端資料並把本機版本另存，可在「資料管理」下載。

## Apps Script

- 拒絕舊的純陣列格式與缺少雲端版本的寫入。
- 內容與雲端相同時直接回傳成功：不寫入、不建立備份批次。
- 先寫入新資料、再清除多出的舊列；列數不夠時自動增加列。
- 類別、詳細內容、備註欄設為純文字格式。
- 回傳的指紋以寫入後重新讀取的內容計算，與下一次 `syncState` 一致。
- 只在表頭不同時才寫入表頭。
- 油價快取最多 3 小時，且不跨過台灣時間週一 00:00 的調價時間。

## 保養與追蹤

- 定期保養：每 7,500 km 或 12 個月，先到者為準；剩 1,000 km 或 30 天內為「可安排」，到達即「該保養」。
- 開車速度：取最近 90 天的每日最高里程（含交車基準點），期間不足 14 天時改用交車以來的平均；推估到達 7,500 km 的日期，行事曆使用預估日與 12 個月期限中較早者。
- 算作定期保養的紀錄：「保養」類別（換位、定位、變速箱、冷氣等專項除外），或「更換／維修」中提到換機油者。
- 追蹤規則各自限定類別，並先移除「檢查、補充、換位、保險桿」等字眼再比對。保險與驗車改為到期前一個月提醒、到期當天顯示該處理。

## 操作體驗

- 新增、編輯、刪除都可從提示列復原；復原以紀錄內容找回目標，期間與雲端合併過也能正確復原。
- 表單有使用者輸入或 AI／照片帶入的草稿時，點背景或按 Esc 不會關閉。
- 加油表單沿用上次的油品、折抵與加油站；里程、金額使用數字鍵盤；即時顯示距上次加油的公里數，疑似打錯時需再按一次儲存。
- 加油分析加入油耗走勢圖（單一系列、平均參考線直接標示、異常點以三角形與「待確認」標示）與每公里油費。
- 資料檢查加入可能重複的紀錄，每個問題都可直接開啟該筆紀錄。

## 效能與離線

- Chart.js 與 Tesseract.js 改為用到時才載入，固定版本並以 SRI 驗證；圖表只在看得到時繪製。
- 每次更新畫面時，排序與油耗統計只算一次；紀錄列表分頁顯示並共用單一事件處理。
- 油價先用本週快取立即帶入，超過一小時才在背景確認。
- AI 只送最近 20 筆紀錄作參考；照片縮到長邊 2,000 px 再辨識，同一次視窗中重複使用 OCR worker。
- Service worker：網站檔案先走網路，3 秒沒回應就用快取；指定版本的 CDN 函式庫優先用快取；資料 API 不經過快取。

## 測試

- `tests/sync-integration.test.js` 以真正的 `app.js` 搭配真正的 `Code.js`（假試算表），涵蓋：刪除後馬上復原、離線儲存後重新開啟、首次讀取失敗、兩台裝置同時修改、回應遺失、空按同步、衝突後的整批還原、舊版本機資料另存、編輯中不替換紀錄。
- 假試算表會模擬 Google Sheets 的自動轉格式，驗證純文字欄位與寫入後的指紋。
- `tests/ux-features.test.js` 涵蓋加油預設值、里程確認、復原、防手滑、重複紀錄、每公里油費、分頁、AI 筆數、油價快取、備份還原、service worker 範圍與 CSS 變數。

## 部署順序

新版前端與舊版 Apps Script 相容，新版 Apps Script 也只會拒絕本來就不安全的寫入。仍建議先部署 Apps Script，確認 `?action=syncState` 正常後再推送網站檔案。
